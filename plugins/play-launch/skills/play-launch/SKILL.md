# 구글 플레이 출시 — 문답형 단계 진행

참고 문서: [reference/guide.md](reference/guide.md) (실제 출시 2회의 경험을 일반화한 체크리스트).
16KB 검사 스크립트: `${CLAUDE_SKILL_DIR}/scripts/check16k.mjs`.

**가이드는 정답표가 아니다.** 콘솔 화면은 자주 바뀌고 계정마다 다르다.
가이드는 화면과 대조하는 용도로만 쓰고, 답은 항상 **지금 보이는 화면과 코드**에서 낸다.

---

## 절대 규칙

1. **화면이나 코드를 확인하기 전에 답하지 않는다.** 메뉴 경로, 선택지 이름, 요건을 기억으로 말하지 않는다
2. **한 번에 한 항목만 안내한다.** 다음 단계를 미리 말하지 않는다
3. 선택지가 있는 항목(태그, 설문, 체크박스)은 **화면에 실제로 나온 목록**에서만 고른다. 목록이 잘려 있으면 전체 목록을 달라고 한다
4. 앱 동작이 답의 근거면 **코드를 열어 확인하고 파일 경로를 근거로 붙인다**
5. 확실하지 않으면 "모른다/확인 못 했다"고 말하고, 구글 도움말을 찾아 **원문을 인용**한다. 기간·요건을 짐작으로 말하지 않는다
6. **예견되는 오류는 미리 처리한다.** "나면 대응"으로 미루지 않는다 (예: 버전 코드)
7. 사용자가 이미 답한 것(키스토어 백업 등)은 다시 묻지 않는다. 받은 답은 기록에 적는다
8. **실제 광고를 누르라고 하지 않는다.** 자기 앱 광고 클릭은 계정 정지 사유다
9. 폰(실기기)을 써야 하면 **사용자에게 먼저 확인받고** 진행한다

## 1단계 — 사전 점검 (콘솔 열기 전, Claude가 직접 한다)

사용자에게 묻기 전에 코드와 빌드에서 확인할 수 있는 것은 직접 확인한다.
`reference/guide.md` §1을 체크리스트로 쓰고, 결과를 표로 보고한다.

| 점검 | 방법 |
|---|---|
| 패키지 이름 | `app.json` / `build.gradle` 의 `applicationId`. **한 번 정하면 바꿀 수 없다**고 알린다 |
| 버전 코드 | 현재 값과 **그 값이 적힌 곳**(gradle 변수까지 추적). 이전에 업로드한 적이 있으면 그보다 크게 **먼저** 올린다 |
| 16KB 정렬 | 릴리스 빌드 후 `node "${CLAUDE_SKILL_DIR}/scripts/check16k.mjs" <stripped_native_libs 또는 푼 AAB>`. FAIL이면 해당 모듈의 CMake에 `-Wl,-z,max-page-size=16384` |
| 서명 | 업로드 키스토어 위치. 백업 여부는 **한 번만** 묻는다. Play 밖에 **실제로 설치된** 배포본이 있는지 묻고, 있을 때만 「자체 앱 서명 키」를 검토한다(guide §1-7) |
| 광고 | 릴리스 빌드에 실제 앱 ID·광고 단위 ID(테스트 ID `3940256099942544` 아님), 매니페스트 `AD_ID` 권한 |
| 출시 국가 · 동의(CMP) | EEA·영국·스위스에 출시하면 UMP 동의 코드가 앱에 있어야 한다. 없으면 출시 국가를 그 밖으로 정하거나 첫 빌드 전에 넣는다 |
| 데이터 보안 근거 | 네트워크 호출(`fetch`/`axios` 등), 저장 위치, SDK가 수집하는 것 |
| 개인정보처리방침 | URL이 실제로 열리는지, 광고 ID 수집을 언급하는지 |
| 개발자 웹사이트 · `app-ads.txt` | 광고 앱이면 스토어 연락처에 넣을 웹사이트를 정하고, 그 도메인 루트의 `app-ads.txt` 가 열리는지 확인한다. 빠지면 AdMob 앱 인증에서 막힌다 |
| 스크린샷 | **9:16 또는 16:9**, 각 변 320~3840px, 24비트(알파 없음), 2~8장 |
| 아이콘 / 그래픽 이미지 | 512×512 32비트 / 1024×500 24비트 |
| 등록정보 문안 | 설명문의 기능·예시를 **코드와 하나씩 대조** |

빌드처럼 오래 걸리는 명령은 백그라운드로 돌린다.
FAIL이나 누락이 있으면 콘솔 단계로 넘어가지 않고 먼저 고친다.

## 2단계 — 콘솔 진행 (사용자가 입력, 문답 반복)

진행 순서의 대략은 `reference/guide.md` §2에 있지만, **실제 순서는 대시보드 할 일 목록을 따른다.**

반복 단위:

```
1. 사용자: 화면 캡처
2. Claude: 그 화면에서 지금 채울 항목 하나 → 입력값 → 근거(코드 경로·문서 원문·화면 문구)
3. 사용자: 입력 후 다음 캡처
```

- 캡처 없이 "다음 뭐 해?"라고 물으면, 추측해서 답하지 않고 지금 화면을 캡처해 달라고 한다
- 콘텐츠 등급·데이터 보안 설문은 **문항마다** 캡처를 보고 답한다. 과거에 기억으로 답했다가 틀린 곳이다
- 테스터 요건(12명·14일 등)은 **대시보드에 그 항목이 보일 때만** 다룬다
- 오류 메시지가 나오면 원인을 찾아 설명하고, 그 뒤에 해결한다. "무시하고 계속하기"는 그 영향을 설명하고 사용자가 정하게 한다

## 3단계 — 제출 후

- 관리형 게시가 꺼져 있으면 심사를 통과하는 즉시 공개된다
- 공개 확인: 게시 개요의 `최근 게시일`, 그리고 `https://play.google.com/store/apps/details?id=<패키지>`
- 광고가 있으면 `reference/guide.md` §3을 따라 AdMob 스토어 연결을 진행한다.
  공개 직후에는 검색되지 않을 수 있다. 공식 문서 기준으로 24~48시간, 최대 일주일이 걸린다

## 기록 남기기

진행하면서 프로젝트에 출시 기록 문서를 만든다(예: `store/play-release-record.md`).
항목마다 **확인됨**(캡처·코드로 본 것)과 **미확인**(사용자가 캡처 없이 진행한 것)을 구분한다.
틀린 안내가 있었으면 "틀린 것 / 원인" 표에 적는다.
이번 출시에서 새로 알게 된 일반적인 사실은 이 스킬의 `reference/guide.md` 를 고칠지 사용자에게 제안한다.
